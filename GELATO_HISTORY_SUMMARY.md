## 2. Root-cause findings (confirmed facts)

1. **The ecommerce API cannot set artwork on a Gelato product — full stop.** Three distinct mechanisms tried (2026-06-13), all return `200` and silently fail to update the mockup/display image: `PATCH /products/{id}/variants/{variantId}` with `fileUrl`; `POST .../print-files` (this one *does* store the actual print file used at print time, but not the display mockup); `create-from-template` with `imagePlaceholders`. *Why it matters:* this is the reason CSV-import-via-UI exists as a manual, Sebastian-owned step at all — it's not a workflow preference, it's the only path that works. — `dayindayin-site/CLAUDE.md` "HARD RULES #0"

2. **CSV import solves artwork-assignment, not catalog-fit.** The same CSV mechanism that reliably assigns the *correct* artwork to the *correct* product is also the mechanism that produced a ~300-product batch that's ~0% print-ready. These are two separable problems: "did the right file land on the right SKU" (solved) vs. "does that file actually work in that template" (not solved, and not currently checkable by any automated step). *Why it matters:* don't conflate "CSV import works" with "the catalog is good." — `dayindayin-site/GELATO_STRATEGY.md` lines 6–19, `dayindayin-site/CLAUDE.md` "HARD RULES"

3. **productUIDs must come from the live template API, never guessed or reused.** Two past silent failures (tote, tank top) from stale/guessed UIDs, each capable of turning a 76-row CSV into 0 or 1 real product. *Why it matters:* this is a mechanical, easy-to-automate check (`scripts/audit-csv-uids.ts`) that has already caught real bugs twice. — `dayindayin-site/CLAUDE.md` "HARD RULES #1"

4. **Shopify's Storefront API masks missing variant photos instead of surfacing them.** It falls back to the product's default image rather than returning `null` (as the Admin API does) — so a customer sees a "broken" selector (click registers, photo doesn't change) with zero signal that anything is wrong. Confirmed systemic: 127/127 multi-variant products. *Why it matters:* this isn't a per-product bug — it's a photography/mockup-coverage gap across the entire multi-variant catalog, same root cause as the crewneck/tote/multi-image problems in the strategy doc. — `dayindayin-site/ISSUES.md` UX-11, `dayindayin-site/LOG.md` 2026-07-11/12

5. **Variant-count sync from Gelato to Shopify was, at one point, completely broken catalog-wide** (all products landed as a single "Default Title" variant despite Gelato holding the full size/frame matrix), compounded by a title-parsing regex bug (`/` assumed, Gelato actually uses ` - `). *Why it matters:* predates and is distinct from the artwork-assignment problem — shows the pipeline has failed in more than one place over time. Appears patched by the 2026-06-24 script burst, but no explicit confirmation-of-fix entry exists in the log. — `dayindayin/ISSUES.md` ISS-01

6. **Two genres of source artwork need different template treatment and the pipeline doesn't distinguish them:** full-bleed-photo-on-colour vs. isolated-graphic-on-transparent. This single fact retroactively explains multiple separate complaints (Neko sizing, tank top/water bottle "white-on-white," SHERO tote crop) that had been logged as unrelated issues. — `dayindayin-site/LOG.md` 2026-06-30, `dayindayin-site/GELATO_STRATEGY.md` line 11

7. **Gelato mockups bake their background into the photo — CSS cannot touch it.** Site-side styling can only affect the card, never what's inside the product photograph. *Why it matters:* closes off an entire class of "just fix it in CSS" instincts (proven wrong once already — the parchment-recolor attempt made things worse) and correctly pushed the real fix (border/matting) to be independent of the Gelato decision. — `dayindayin-site/GELATO_STRATEGY.md` lines 21–23, `dayindayin-site/LOG.md` 2026-07-03

8. **Publish mutation format gotcha:** Shopify's publish-to-Online-Store mutation requires `input: [{ publicationId: "..." }]`, not `publicationIds`. — `dayindayin-site/CLAUDE.md` "Publish script" note

## 4. Recurring failure patterns ("watch out for this again")

- **productUID drift.** Happened twice already (tote, tank top) — both silent, both would have nuked a 76-row batch. Always re-run `scripts/audit-csv-uids.ts` against the live template API before any import; never reuse a UID from memory or an old CSV.
- **Guessing at the site-CSS layer to fix a Gelato-baked-in problem.** The parchment-recolor attempt (2026-07-03) made the background clash worse because it didn't account for the mockup's own baked-in white.
- **Mis-attributing an artwork/genre difference to a template/size difference.** The Neko poster "size mismatch" was blamed on A4-vs-A3 before the actual cause (artwork background type) was found.
- **API silently succeeding while doing nothing.** All three attempted API-based artwork-assignment mechanisms returned 200 with no error, and the variant-sync bug also failed silently.
- **Stale/uncommitted ISSUES.md drifting from reality.** The board sat unreconciled for 9+ days on two separate occasions, during which real fixes shipped without tickets being closed.
- **Assuming a photo problem is fixable by picking a different existing photo.** Repeatedly, the correct call was "no valid photo exists in the asset library at all" rather than swapping to another wrong one — same underlying pattern as the missing-per-variant-photo Gelato problem.

## 5. Suggested angles for the Cowork reassessment

1. **Is CSV-import-via-Gelato-UI still the right production mechanism at all, given the volume now in play?** It was adopted as "the only verified path" when the alternative was a fully-broken API. But it's a manual, Sebastian-owned bottleneck that has now twice produced catalog-wide breakage for two entirely different reasons. Worth asking whether the real fix is a better CSV *generation* discipline (pre-validated buckets: orientation, genre, single-vs-multi-image) rather than relitigating the import mechanism itself.

2. **Curation quality is being treated as an artwork-selection problem, but at least two of the six failure modes (template variant-completeness, multi-image content assignment) are template-authoring problems that live entirely on Sebastian's side of the division of labor.** Should "curate to 150" include a parallel pass of *fixing the templates themselves*, or is the plan to route around broken templates rather than repair them?

3. **The paid-tier question has been open since 2026-07-01 with zero research done.** Before committing to either "curate by hand forever" or "patch the automation," it seems worth spending an hour finding out what the paid tier unlocks — the cheapest open question to close, and possibly the one that reshapes the whole decision.

4. **The 127/127 missing-variant-photo gap and the ~0% print-ready finding are being tracked as the same open decision, but they may need different fixes on different timelines** — one is "which artwork should exist as a product" (curation), the other is "does every existing variant have its own photo" (a photography/asset-generation gap that exists even for the ~10 already-verified-correct products). Worth explicitly separating these into two decisions.

5. **Nothing in the record ties the Gelato catalog-correctness question to actual commercial risk or timeline.** The one real-risk question asked twice ("is any of the broken batch live/orderable") got a reassuring answer only because the site is still on a temp Vercel URL — that safety net disappears the moment `dayindayin.dk` DNS goes live (still an open Gate-6 item per `LAUNCH.md`). Worth explicitly deciding: does DNS/launch wait on this catalog decision, or does the catalog decision need to be forced by a launch deadline?
